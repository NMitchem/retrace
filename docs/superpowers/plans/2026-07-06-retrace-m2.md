# retrace M2 — The Loader (MMU-on, dyld, PAC, shared cache) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get a normally-compiled, dynamically-linked C program running inside the box by letting *real dyld* load it, and record + replay it with zero divergence — MMU on, PAC on, the shared cache mapped by dyld itself.

**Architecture:** retrace-box emulates only the kernel's process-setup contract: build a guest-side identity stage-1 page-table map (MMU on, Normal memory), set fixed PAC keys, map the main Mach-O and `/usr/lib/dyld` (arm64e) into **anonymous** guest pages, build the initial stack (`argc/argv/envp/apple[]`, `DYLD_SHARED_REGION=private`), and jump to dyld's entry. Real dyld then maps the dyld shared cache itself via ordinary `open`/`mmap`/`pread` syscalls, which the M1 memory-diff recorder already traps and forwards. We write no shared-cache parser. The M1 trace format, divergence oracle, and seeded swarm carry forward; M2 pays the four recorder debts M1 deferred.

**Tech Stack:** Rust 1.95, Hypervisor.framework via the in-tree `hv-sys` crate, a raw `svc #0x80` shim for host syscall forwarding (record only), `clang` for guests, real system `/usr/lib/dyld` + dyld shared cache.

## Global Constraints

- **Platform:** Apple Silicon, macOS 26.x (spike host: 26.4.1 / build 25E253). Target `aarch64-apple-darwin`. Builds on M1 (merged to `main`); **all M1 tests must stay green after every task**.
- **Entitlement:** every `hv_*`-calling binary is ad-hoc codesigned with `com.apple.security.hypervisor` via the cargo runner (`tools/codesign-run.sh`). A test-spawned `CARGO_BIN_EXE_*` binary must be codesigned in the test helper (see `crates/retrace/tests/e2e.rs::bin()`).
- **One VM per process.** In-process VM tests create at most one VM per test; run VM tests with `--test-threads=1`. End-to-end record→replay tests drive the `retrace` CLI as separate subprocesses.
- **SPTM HARD RULE (load-bearing, learned the hard way — see spike):** NEVER `hv_vm_map` a file-backed page. On macOS 26 that hard-panics the machine (`[SPTM] VIOLATION_ILLEGAL_MAPPING_TYPE`). All guest memory is **anonymous** (`MAP_ANON`); file bytes (dyld, the cache, the executable) are read/`pread`/`fread` into anon pages, and those anon pages are mapped. This is why every `hv_vm_map` in the codebase targets an anon buffer; keep it that way.
- **Identity VA==IPA preserved.** MMU is on, but the stage-1 map is identity (guest VA == IPA), so M1's pointer arithmetic (`host = backing.host + (guest_ptr - backing.ipa)`) is unchanged and forwarded-syscall pointers stay valid. Stage-1 permissions are uniform Normal EL0-RWX; the security boundary remains stage-2 + the VMM, exactly as in M1.
- **Fixed PAC keys.** The five pointer-authentication key registers are set to compile-time constants, identical on record and replay, so pointer signing is deterministic. Keys live in `retrace-box` as named consts.
- **No syscall executes during replay** (negative-space invariant): replay applies recorded `writes`, feeds recorded `ret`, and restores the recorded carry flag; it never issues an `svc`. `retrace-core` still must NOT depend on `hv_sys`/`libc`.
- **Assertions stay on in release** (`assert!`, not `debug_assert!`). Divergence/abort messages name the contract, the site, and the fix, and print the seed + a one-command repro.
- **Syscall numbers (macOS arm64 BSD, in `x16`, `svc #0x80`):** existing M1 set plus `mmap=197` (already), and mach traps arrive as negative syscall numbers (`x16 < 0`, e.g. `mach_reply_port=-26`, `task_self_trap=-28`, `_kernelrpc_mach_vm_map_trap=-71`); M2 discovers exactly which are needed in Task 9.
- **License:** MIT OR Apache-2.0; clean-room. Real dyld and the cache are loaded, never copied into the repo.

In `crates/retrace-box/src/lib.rs` add the const, the table builder, and wire `load`/`restore`:
```rust
pub const PT_IPA: u64 = 0x8000;               // 16 KiB L2 table backing (free: below trampoline)
const TCR_EL1_V:  u64 = 0x1_0080_B51C;        // T0SZ=28, TG0=16K, WBWA, inner-share, EPD1, IPS=36-bit (spike-proven)
const MAIR_EL1_V: u64 = 0xFF;                 // attr0 = Normal WBWA
// base 0x30d00800 + M(1) + C(4) + I(0x1000); PAC enable bits are added in the PAC task.
const SCTLR_MMU_ON: u64 = 0x30d0_0800 | 1 | 4 | 0x1000;
const BLOCK_ATTRS: u64 = 0x400 /*AF*/ | 0x300 /*SH inner*/ | 0x40 /*AP EL0RW*/ | 0x1 /*block*/;

impl Box_ {
    // Build a flat identity map: 2048 L2 block descriptors, each covering 32 MiB, Normal
    // EL0-RWX (UXN=PXN=0). Covers the whole 36-bit VA space, so any future guest_mmap IPA is
    // already mapped. Access to an IPA with no stage-2 backing still faults to the VMM.
    fn build_identity_tables(backings: &mut Vec<Backing>) -> u64 {
        let (host, len) = alloc_pages(GRANULE);   // one 16 KiB page = 2048 * 8 bytes
        let table = unsafe { std::slice::from_raw_parts_mut(host as *mut u64, 2048) };
        for (i, e) in table.iter_mut().enumerate() {
            *e = ((i as u64) << 25) | BLOCK_ATTRS; // block base = i * 32 MiB
        }
        // SAFETY: anon backing (SPTM-safe), mapped 1:1 like every other region.
        // (vm.map is done by the caller alongside the other backings.)
        backings.push(Backing { host, ipa: PT_IPA, len });
        PT_IPA
    }
}
```
In `load`, after the segment/stack/trampoline maps and before setting registers, build + map the tables and switch the sysregs (replace the `SCTLR_EL1 <- 0x30d00800 (MMU off)` line):
```rust

        // map the table backing into stage-2 (same helper the other maps use)
        vm.map(backings.last().unwrap().host, ttbr0, GRANULE, MemFlags::RWX).expect("hv_vm_map (pt)");
        vcpu.set_sys(sysreg::MAIR_EL1, MAIR_EL1_V).unwrap();
        vcpu.set_sys(sysreg::TCR_EL1,  TCR_EL1_V).unwrap();
        vcpu.set_sys(sysreg::TTBR0_EL1, ttbr0).unwrap();
        vcpu.set_sys(sysreg::SCTLR_EL1, SCTLR_MMU_ON).unwrap();   // was 0x30d00800 (MMU off)
```

## M2 → M3 boundary

M3 is instruction-exact positioning — single-step counting from landmarks, interval snapshots, and hardware breakpoints — so replay can stop at an exact instruction across record and replay. The MMU, PAC, loader, and full syscall/mach surface built here carry forward. Items this milestone leaves for later:

- **Stack/`apple[]` minimalism.** T7 builds the smallest start stack dyld accepts; a real interpreter (M6) may need more `apple[]` entries (entropy, `dyld_file=`, `executable_file=`, `main_stack=`). Widen as programs demand; the oracle flags a miss.
- **`mprotect` is fidelity-only.** Stage-2 stays RWX; a program relying on a real protection fault won't get one. Fine for benign M2/M3 targets; revisit if a guest depends on `PROT_NONE` guard-page faults.
- **Whole-cache mapping cost.** File-backed mmap `pread`s the whole requested extent eagerly and records it as `writes`; a large interpreter could make traces big. Compression is deferred post-v1 (master spec); measure before optimizing.
- **Commpage/`CNTVCT` instrumentation** is only added in T9 if dyld trips it; systematic read-site handling is M5's hardening.

## Risk register

1. **Unknown count of dyld special cases (schedule).** T9 is discovery, not construction; the number of mach traps/nondeterministic inputs dyld startup needs is not known until it runs. *Mitigation:* the oracle bounds every miss to a named, seed-reproducible failure; T9 front-loads the harness so each iteration is minutes. If the tail is long, ship the handlers found and pin the rest as follow-ups — the gate (`hello_dyn` green) is a fixed target.
2. **`MAP_FIXED` cache address outside the identity map.** If dyld maps the cache above 64 GiB via `MAP_FIXED`, the stage-1 block map wouldn't cover it. *Mitigation:* the observed arm64e cache sits ~6 GiB (block 195, well inside 64 GiB); if a build differs, widen the identity map (more L2 blocks or add an L1 level) — a localized change in `build_identity_tables`.
3. **PAC key/layout determinism.** Any signing that depends on state we don't fix diverges. *Mitigation:* fixed keys + identity VA==IPA + fixed MMU layout; the oracle flags residual nondeterminism; PAC can be disabled (`EnIA=0`, spike-verified) to bisect a suspected PAC divergence.
4. **Trace-format churn.** T5 bumps the format (`err` field). *Mitigation:* the magic/version byte already rejects stale traces loudly (M1 t2); no silent misread.
5. **retrace-box growth.** The crate gains MMU/PAC/loader/forward logic. *Mitigation:* the T2 note mandates a module split past ~450 lines, keeping `Box_`'s public surface stable.
6. **SPTM re-panic.** Any new `hv_vm_map` on a non-anon page re-panics the host. *Mitigation:* the Global-Constraints hard rule; every mapping site in this plan takes an anon buffer; code review greps for `hv_vm_map` + file descriptors.

## Non-goals / explicitly deferred

- Any shared-cache format parsing (we run real dyld).
- Multi-threaded startup, signals, positioning, the debugger seam (M3+).
- Enforced `mprotect` protections / `PROT_NONE` guard-page faults.
- Recording untrusted/adversarial binaries at full hardening — the write-extent clamp (T4) is the one memory-safety fix pulled forward because it is trivially reachable by real reads.
- Cross-machine / cross-OS trace portability (same-chip-class, pinned build; unchanged from M1).
- Trace compression (deferred post-v1 per the master spec).

## Open questions for implementation planning

- **PAC enabled vs. disabled for first bring-up (T9).** Leaning enabled (spike shows it works; disabling risks masking a real determinism bug); flip to `EnIA=0` only to bisect a suspected PAC divergence.
- **Exact `apple[]`/env minimum (T7/T9).** Determined empirically against real dyld; the oracle flags anything missing. Start with `DYLD_SHARED_REGION=private` + executable path.
- **File-backed mmap eager vs. lazy (T8).** Eager whole-extent `pread` chosen (simple, deterministic); revisit only if cache-sized mappings make traces unwieldy.
- **Where the raw-`svc` shim lives (T5).** In `retrace-box` via `core::arch::asm!` (chosen), keeping the forwarding path under the box's control rather than widening `hv-sys`.
